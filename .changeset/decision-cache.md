`pick` gains an optional decision cache that stores each answered decision. With `cache: { store, deciderId }`, where `store` is an asynchronous `get`/`set` port and `decisionFileStore(directory)` is the supplied implementation (one JSON file per answer, written to a temporary file and renamed into place), a later pick over an unchanged part reuses its stored answers instead of asking the decider again. Each answer's key is a SHA-256 over the task text, the question-set version, the rendered question's wording, criteria, and fitted name and tag set, the caller's `deciderId`, the text cut, and every field of the part the decider receives (its source id, id, title, role, kind, date and text), so answers are reused across batches: a later batch that gains or changes one part asks only that part. A refused, missing, errored or never-asked answer is never stored, and every failed read is a miss.

A stored answer marks its record entry `reused`. It marks a selected or rejected entry when every decision behind it came from the store, and it marks each per-question and tag answer. `record.cache` reports the question-set version, the deciderId, how many decision and tag questions the decide port was asked, how many were reused, and `failedWrites`. Label questions go through the same port but are not counted in `cache.asked`: `record.labels.asked` counts each asked item once, one question per label kind each. When `failedWrites` is above 0 one `warning` is recorded; the pick still uses those answers. Pass `cache: false` to bypass a configured cache for one pick: nothing is read or written. The option is off by default: with `cache` unset the output is identical to a pick without it.
